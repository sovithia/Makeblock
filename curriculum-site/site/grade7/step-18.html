Teach it — the concept

Find a group of blocks you have copied more than once. That is a function waiting to happen. Make a Block, give it a name, put the blocks inside, and now the program says celebrate instead of nine blocks — and changing the celebration means changing it in one place instead of three.

One honest limitation, worth saying plainly rather than letting them discover it as a disappointment: these blocks are procedures, not answers. There is no "return". A block cannot hand a value back. If scan needs to report whether it found something, it sets a variable and the caller reads it. That is a real pattern, not a workaround.

Function — My Blocks
A function is a piece of program you name, so you can use it by name afterwards. This is the biggest idea in the course. It does two things at once: it stops you writing the same blocks twice, and — more importantly — it lets the main program say what it is doing rather than how. Fixing the behaviour later means fixing it in one place. In mBlock these are called My Blocks; everywhere else they are called functions, procedures or methods.
Watch out
  • Name blocks after what they do, never how they do it. celebrate survives being rewritten; spin_and_beep does not.
  • The no-return limitation catches everyone. Teach the variable pattern once, properly, and it will be reused in Steps 17–23.
  • A team whose main program is now five blocks long has understood the whole point. Show it to the class.
