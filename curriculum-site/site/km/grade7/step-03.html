Two ideas hold up everything else. A sequence is instructions in order — the robot does one, then the next, and swapping two lines changes what happens. An event is what starts a sequence running. Nothing runs on its own: something has to happen first — the robot powering on, a button going down. Every program you write this year is sequences waiting on events.

ថ្មី when CyberPi starts up — Runs the blocks under it the moment the robot powers on, with no tablet attached. This is what makes a program the robot's own rather than the computer's. · set print size to small — Changes the size of printed text. · print and move to a newline — Adds text and moves to the next line, so repeated prints stack down the screen like a list. · LED all displays R G B — Sets one of the five lights, or all of them, by mixing red, green and blue from 0 to 255. · play LED animation rainbow until done — Plays a built-in light pattern and waits for it to finish. · when button A pressed — Waits for button A or B on the robot and runs what is under it. Several of these can sit in one project, each on a different button. · play recording — Plays back audio you recorded onto the robot yourself. · ultrasonic 2 1 displays emotion standby — The eyes on the ultrasonic sensor are a display of their own. Cheap, obvious feedback about what the robot thinks is going on. · clear screen — Wipes the screen. Inside a loop it is what stops old text showing through the new. · print — Adds text to the screen where the last print left off. · turn off LED all — Turns lights off. Worth its own block, because a light left on reads as the program still running.
