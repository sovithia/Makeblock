Teach it — the concept

Sensors in Python return numbers you can hold in a variable: off = cyberpi.quad_rgb_sensor.get_offset_track(). That one line changes the relationship — in blocks, values flowed invisibly; in Python, students capture, print, compare and compute with them. Build the classic diagnostic tool first: a loop printing the live readings to the screen ten times a second (a dashboard, and their debugging best friend for the rest of the year).

This robot senses the floor and its own wheels — there is no ultrasonic anywhere on the Rover, so nothing here measures the air in front of it. Two numbers matter all year. The Quad RGB reports how far off-centre the line is (an offset, roughly −100…+100): push the robot along a line by hand and watch it swing negative–zero–positive — that number IS next week’s error signal. The encoders report how far each motor has turned in degrees: push the robot forward by hand and watch the angle climb — that number is Session 9’s ruler.
Python (mBlock → Python mode)
import cyberpi, mbot2, time mbot2.EM_reset_angle('EM1') while True: off = cyberpi.quad_rgb_sensor.get_offset_track() deg = mbot2.EM_get_angle('EM1') cyberpi.display.show_label( 'off=' + str(off), 16, 'top') cyberpi.display.show_label( 'deg=' + str(deg), 16, 'center') if cyberpi.quad_rgb_sensor.is_color('red', 'l1'): cyberpi.display.show_label( 'MARKER!', 24, 'bottom') time.sleep(0.1)
Watch out
  • Function names below follow mBlock’s CyberPi Python API; minor names vary by version — the class rule is: trust the editor’s autocomplete.
  • str(off) trips everyone — numbers must become text to display; let them hit the error, then explain.
  • Calibrate the line sensor first (the Grade 7 ritual) or the offset numbers are noise.
  • Someone will go looking for the distance sensor: the Rover does not carry one, and that absence is the reason Session 9 exists.

① Recap & Debug 10′

Predict the number first. Before pushing the robot along the line, each pair writes what the offset will read in three positions: line hard left, dead centre, line hard right. Then push and check. Getting the sign backwards is common, and it is far cheaper to discover here than in Session 6, where an inverted sign makes the robot flee the line.

④ Extend — to spec 25′
  • 3 values live Offset, encoder angle and the marker flag all updating on the dashboard at once.
  • encoder read against a ruler Push the robot exactly 30 cm by hand and write down the degrees. Session 9 turns that pair of numbers into a conversion.
  • offset explained physically What offset = −60 means, drawn, with the sign convention written down explicitly.
⑤ Engineering Log 10′

The sign convention in a box on the printed lesson sheet — which way is positive — plus the three predicted and actual offsets side by side. Session 6 reads this box, so a convention recorded vaguely costs a session's tuning to an inverted term.

⑥ Design Review 15′

Pairs explain their sign convention to another pair. Criteria — do the two pairs agree, and where they do not, is it a genuine difference in how the sensor is mounted or simply a drawing error?
