Teach it — the concept

Full control flow: if / elif / else and while. The vehicle is deliberately nostalgic — rewrite Grade 7’s wander mode in Python. But Grade 7’s robot escaped from a distance, and this one has no ultrasonic, so the same behaviour has to be built on a different sense: a taped boundary on the floor, and the Quad RGB probes that see it. Say that out loud as the day’s real lesson — the behaviour is not the sensor. Roam, notice the edge, back off, turn away, roam again: that shape is unchanged since Grade 7, and only one line of it knows what a sensor is.

Then introduce refactoring: improving code’s shape without changing its behaviour. Extract the escape manoeuvre into escape(), extract the sensing into on_edge(), name the magic numbers as constants (BACK_CM = 10), and re-run — identical robot behaviour, radically clearer code. Then land the point: because the sensing lives in on_edge(), swapping the robot’s eyes again would touch two lines. That “same behaviour, better shape” discipline is the heart of code quality, and it is a rubric line in the capstone code review.
Python (mBlock → Python mode)
import mbot2, cyberpi, random CRUISE = 40 # RPM: quick, but stoppable BACK_CM = 10 # far enough to clear tape def sees(probe): return cyberpi.quad_rgb_sensor.is_color( 'black', probe) def on_edge(): # no ultrasonic: the edge is a colour return sees('l1') or sees('r1') def escape(): mbot2.straight(-BACK_CM) mbot2.turn(random.randint(60, 120)) while True: if on_edge(): escape() else: mbot2.drive_speed(CRUISE, CRUISE)
Watch out
  • random.randint needs the import — a good ‘read the error’ moment.
  • ‘Why not what’ comments: # far enough to clear the tape, not # set BACK_CM to 10.
  • If the robot reverses onto the boundary and sticks there, BACK_CM is smaller than the wheelbase behind the probes. Measure it rather than guessing.
  • Tape the boundary wide — a thin line at speed is crossed between two sensor reads, and that is a genuine sampling lesson, not a bug.

① Recap & Debug 10′

Record the behaviour before touching it — three arena runs with the original code, timed, boundary crossings counted. Without that baseline, "behaviour unchanged" is an opinion, and the whole point of the word refactoring is that the claim can be checked.

④ Extend — to spec 25′
  • identical, measured The same three-run measurement after refactoring, landing inside the spread of the before.
  • 0 magic numbers Every threshold a named constant, defined in exactly one place.
  • sensing in one function Exactly one function knows what the robot senses with. Change the colour of the tape and only that function needs reading.
⑤ Engineering Log 10′

Before-and-after measurements side by side, with the before-and-after code snippets beneath them. The question on the lesson sheet is the honest one: which of these two would you rather be debugging at 11 pm?

⑥ Design Review 15′

Another pair reads the refactored version cold and states what the robot does. Criteria — could they say it without seeing the original, and did the named constants help, or did they just add a layer to chase?
