Teach it — the concept

The Rover can now drive, approach smoothly, and grip. It needs to know which job it is on — idle, fetching, carrying, delivering — and that is one variable holding a word, with a short main loop that reads it and runs the matching block.

The interesting work is the arrows: what ends fetching and starts carrying? Gripping something. What ends carrying? Arriving. Draw them on paper first, then look for the ones you did not draw — the arrow out of "I tried to grip and missed" is the one every team forgets, and it is the one that strands the robot in the mission.

Watch out
  • A job with no way out is a trap, and every class builds one. Finding it by trying to strand the robot is the lesson, not a failure.
  • The job name on screen makes every later bug visible from across the room. Do not let anyone skip it.
  • Foam blocks and a generous drop zone today. Precision comes in Stage E.

Lesson flow — minute by minute

20′On paper: four boxes, arrows between them, the condition on each arrow. No blocks yet.
✓Four boxes on paper with a condition written on every arrow. No blocks yet.
25′Build the mode variable and the main loop. Each job calls blocks you already have.
✓One variable holding the current job, and a main loop that hands each job to blocks you already own.
25′Wire the transitions and show the current job on screen as a word.
✓Every arrow works on the robot, and the screen says in a word which job it is doing.
25′Now break it: what happens if the grip closes on nothing? Add the arrow you did not draw.
✓You close the grip on nothing and the robot recovers instead of freezing — the arrow you had not drawn.
15′Full cycle: fetch a foam block, carry it a metre, deliver it, return to idle. Three times running.
✓Fetch, carry a metre, deliver, return to idle — three times in a row without help.
10′Log the diagram, marking the arrows you added only after testing. Step 22 designs the real job starting from this diagram.
✓The diagram in the log with the arrows you only found by testing marked. Step 22 starts from it.
◉ Expected result at the end of this session
ABUTTON
The press A to start message goes, and the screen shows job idle instead. Idle is a job like any other — having nothing to do is a state, not a bug.
←JOYSTICK
The word on screen changes from idle to fetch and it drives off hunting for the red patch. One push of the joystick moved it along one arrow of the diagram.
👁WATCH FOR
On the patch it stops, grips, and the screen says carry; it drives a metre, says deliver, lowers the arm, lets go, and comes back to idle. Four jobs, four arrows, nobody touching it.
Teacher check
  • Four jobs, each labelled on screen and each escapable
  • A full fetch-carry-deliver cycle, three times running
  • At least one arrow added after testing that was not on the original diagram
